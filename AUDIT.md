# AEGIS — аудит 0.6.0 и исправления в 0.7.0

Дата: 14.10.2026. Ветка `claude/audit-hardening` от `903c2f0` (v0.6.0).
Все запуски, сборки и браузерные проверки — внутри Windows Sandbox (Windows 10 Enterprise 10.0.19041, 8 ГБ, без физической GPU). На основной Windows только редактирование исходников, git и упаковка ZIP.

Метки: **[воспроизведено]** — увидено в работающем госте; **[по коду]** — подтверждено чтением кода; **[гипотеза]** — не проверено.

## P0. Жалоба «нет реальных данных, проверок, синих экранов; плохие графики»

### A1. У пользователя открыт старый AEGIS 0.5.0, а не релиз 0.6.0 — [воспроизведено]
- **Симптом:** окно Edge `--app=http://127.0.0.1:8765` показывает интерфейс 0.5.
- **Доказательство:** снимок гостя 14.10 00:30 — на 8765 слушает `Work\AEGIS\Aegis.Agent.exe` версии 0.5.0.0, данные `Work\AEGIS-state` (Evidence/run-…/, `before-user-window-0.5.0.png`).
- **Причина:** (1) прошлое тестовое задание `SandboxControl\068-…` после проверки 0.6 само перезапустило старый `Work\AEGIS\scripts\start-aegis.ps1`; (2) `start-aegis.ps1` 0.6 считал «готовым» любой AEGIS на порту (`Test-Ready` не сверял версию и путь), поэтому запуск 0.6 просто открывал окно старого агента.
- **Исправление:** `scripts/aegis-common.ps1` + новый `start-aegis.ps1`: читает FileVersion своего `Aegis.Agent.exe`, сравнивает версию **и** путь процесса на порту; при другой копии AEGIS спрашивает разрешение и останавливает только процесс `Aegis.Agent` (по PID из `/diagnostics`, с проверкой имени); служба Windows и чужие программы не трогаются — выдаётся понятная причина. Добавлены `Stop AEGIS.cmd`, `Diagnose AEGIS.cmd`.
- **Проверка:** задание 106 — при живом 0.5 новый лаунчер вернул exit 1 и «Порт 8765 занят другой копией AEGIS (версия 0.5.0.0, PID 5584, файл …\Work\AEGIS\Aegis.Agent.exe)», старый агент остался работать. Из папки исходников — «Это папка с исходниками, а не готовая программа…».

### A2. Тесты лаборатории были незаметны — [воспроизведено/по коду]
- **Причина:** CPU — 1 поток ≤80% (на 12 логических CPU ≈4% общей загрузки), RAM ≤128 МиБ, диск ≤32 МиБ (доли секунды), сеть 3 МиБ. Описание лаборатории говорило только о CPU/RAM; выбор теста только рулеткой.
- **Исправление:** прямые кнопки CPU/RAM/GPU/DISK/NET + рулетка как опция; CPU 1…N потоков, 10–100%, до 60 с; RAM до 2 ГиБ блоками по 64 МиБ с удержанием; GPU — тяжёлый шейдер с регулируемой сложностью и выводом реального рендерера (SwiftShader помечается как программный); DISK 64 МиБ…1 ГиБ с проверкой свободного места (размер + 2 ГиБ резерва); NET — непрерывный loopback по 1 МиБ в течение времени теста. Живой график с подсвеченной зоной теста, таймер, «Стоп», запись в журнал аудита.
- **Проверка (106, Playwright в госте):** CPU 6 потоков → 37–47% общей загрузки в UI; RAM 512 МиБ → RAM 31→38%; GPU 9 FPS, SwiftShader, CPU 87%; DISK 256 МиБ запись 541 / чтение 3675 МиБ/с, содержимое проверено; NET 779 МиБ за 10 с по loopback; «Стоп» на 5-й секунде → «Остановлен, ресурсы освобождены». 0 ошибок JS.

### A3. Синего экрана «нет» — [воспроизведено/по коду]
- **Причина:** демонстрация спрятана за кнопкой «Управление питанием» (иконка ⏻ отображалась квадратом), фон после перевода UI в ч/б стал серым `#656565` (F9), после 100% экран сам уходил в «фейковое выключение».
- **Исправление:** кнопка «Показать синий экран» в Лаборатории и «Синий экран / питание» в меню; настоящий синий Win10 (`#0078d7`), русский текст, QR-блок, стоп-код `AEGIS_SIMULATED_SYSTEM_FAILURE`, явная плашка «ДЕМОНСТРАЦИЯ — Windows работает», выход Esc/кнопкой. Синий — единственный цвет в программе и только в этой демонстрации. Реальное выключение Windows осталось отдельной функцией (ввод ВЫКЛЮЧИТЬ, 45 с на отмену); автоматически не нажималось.
- **Проверка:** фон `rgb(0,120,215)`, Esc закрывает (06-bsod.png, 07-after-bsod.png).

### A4. Графики — [воспроизведено]
- **Было:** одна линия без оси Y и значений, растянутый SVG (`viewBox` 760×230 с искажением текста), RAM/GPU сливались, пропуски данных соединялись прямой.
- **Стало:** `frontend/charts.js` — ось Y (0–100% или авто-шкала Б/с), подписи времени, сетка, легенда с текущими значениями, «нет данных» вместо выдуманных чисел, разрывы при пропусках, подсказка при наведении, отрисовка по реальной ширине (без искажения). Ч/б: серии различаются толщиной и пунктиром. Обзор: история CPU/RAM/GPU + сеть (15 мин–24 ч из SQLite). Мониторинг: живые графики 1–10 мин. Лаборатория: 90 с с зоной теста.

### A5. Пустое/ложное состояние без связи — [по коду]
- Добавлен баннер: «Нет связи с AEGIS Agent», «Данные устарели», «Интерфейс открыт как файл». API/WebSocket берутся из `location.origin` (раньше жёстко `127.0.0.1:8765`). Недоступные датчики подписаны («датчик недоступен», «часто в VM»). Убран статичный «Оператор SOC / Смена №42» — вместо него имя компьютера и версия агента.

## Итерация 3 (14.10.2026, ночь) — сеть, доступ, камеры, логи, служба

Проверено на физическом ПК пользователя (Ryzen 5 7500F, RTX 3070, без прав администратора):
- **Сеть:** живой список соединений с процессом, узлом, сервисом, зоной (этот ПК / LAN / провайдер / интернет) и направлением; журнал в SQLite (7 дней, CSV). Байты по соединениям и процессам — только в режиме службы (TCP EStats требует повышенных прав).
- **Логи агента:** ежедневные файлы <данные>\logs\aegis-YYYYMMDD.log, 14 дней, просмотр в «Журнале аудита».
- **Контроль доступа:** входы Windows (4624/4625/4634/4647/4740/4800/4801/4778/4779), правило подбора пароля и блокировок, приём событий физической СКУД (POST /api/v1/access/events с токеном). Без службы честно показывает «нет доступа к журналу безопасности».
- **Камеры:** HTTP snapshot/MJPEG только для локальной сети, детектор движения → инцидент; веб-камера через браузер. На ПК пользователя камеры нет — проверено только юнит-тестами разбора MJPEG и ограничений адресов.
- **Служба:** install-service.bat сам запрашивает UAC, останавливает консольный агент, переносит данные в %ProgramData%\AEGIS. **Не устанавливалась** — нужен пароль администратора.
- **Чат по LAN:** relay с собственным CA (90 дней) без добавления CA в доверенные на этом ПК; HTTPS проверяется по файлу CA. **Не запускался в LAN-режиме** на ПК пользователя.
- **Температура CPU:** LibreHardwareMonitor 0.9.6 требует драйвер PawnIO; без него — «недоступна» с объяснением в UI.

Написано, собрано (116/116 тестов), но в итерации 3 **не подключено к API/UI** (подключено в итерации 4): диски (SMART/MSFT_PhysicalDisk), Microsoft Defender (статус, обнаружения, проверка через MpCmdRun), открытые порты TCP/UDP с владельцем, проверка подписи файлов, схема БД v4 (таблицы очереди подтверждений, журнала устройств, правил брандмауэра).

**Не сделано в итерации 3:** режим контроля (базовое состояние + очередь «Разрешить / Отметить как угрозу») и блокировка по кнопке. Работа над режимом контроля несколько раз прерывалась фильтром безопасности ассистента; оставлено пользователю на доработку.

## Итерация 5 (14.10.2026, вечер) — служба Windows на ПК пользователя

Служба установлена пользователем (LocalSystem, автозапуск), сборки 117–119 (158/158 юнит-тестов). Проверено:
- **Права службы:** журнал безопасности читается (входы, неудачные входы); правило «Подбор пароля» сработало на 5 неверных паролей при подтверждении UAC; трафик по процессам (TCP EStats); SMART-прогноз для SATA-дисков (NVMe и виртуальный диск Windows его не публикуют — «нет данных»).
- **Брандмауэр:** «Закрыть сеть» создала правило блокировки (вход и выход) для тестовой программы, снятие кнопкой удалило его из брандмауэра Windows; оба действия в аудите.
- **Лаунчер** при работающей службе отвечает «AEGIS готов» и второй агент не запускает. **Автоперезапуск:** процесс службы завершён принудительно — Windows подняла его заново (действия при сбое 5/15/60 с).
- **Перенос данных** консольного режима (14 инцидентов, базовое состояние контроля 366) выполнен; прежняя база службы сохранена резервной копией.

Найдено и исправлено:
- Перенос данных при установке не срабатывал, если установщик видит не ту папку `%LOCALAPPDATA%` (повышение под другой учётной записью или иное представление профиля): теперь установщик ищет данные по всем профилям, есть `migrate-service-data.bat`, и служба никогда не остаётся остановленной.
- Ложный критический инцидент «Возможная остановка охлаждения»: 94 °C — это порог NVMe («Critical Temperature»), а 0 RPM у RTX 3070 — тихий режим при 49 °C. Пороговые значения больше не считаются температурой; правило сравнивает горячее устройство с его собственными вентиляторами.
- Код отказа входа показывался числом (-1073741718) — теперь «неверный пароль».
- Системные файлы Windows без встроенной подписи (подписаны каталогом) шли в режиме контроля как «без подписи»: файлы, принадлежащие TrustedInstaller, теперь «компонент Windows», низкий риск; риск элементов в очереди пересчитывается при каждой проверке.

**PawnIO** (по решению пользователя): официальный подписанный установщик 2.2.0 (GitHub namazso/PawnIO.Setup, SHA-256 сверен, подпись namazso.eu действительна). После установки служба читает Ryzen 5 7500F (Tctl/Tdie, CCD1), Nuvoton NCT6687D (VRM, сокет, PCH), DDR5 и вентиляторы платы. Исправлено (сборка 120, 161/161): PawnIO — драйвер ядра, определяется через список драйверов; «Temperature Sensor Resolution» у DDR5 и 0 °C неподключённых датчиков платы не показываются как температура.

Не проверено: LAN-чат со второго устройства (пользователь отложил), Windows 11.
